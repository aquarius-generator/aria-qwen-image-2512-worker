# EVERY VERSION IS EXACT, AND THAT IS THE FIX.
#
# Build 1 died at the 1800 second ceiling downloading 57.7 GB of weights. Build 2 took 7.7 minutes and then
# every job failed, because diffusers 0.33.1 has no QwenImagePipeline. Build 3 corrected diffusers but used
# RANGES for transformers, accelerate and huggingface-hub, and hit the ceiling again at over 30 minutes
# without downloading any weights at all. The cost was pip BACKTRACKING: an unbounded set over a tree that
# includes torch makes the resolver try version after version, and that search alone can outlast the whole
# build budget.
#
# So nothing here is ranged, and the set was checked against each package's own published metadata rather
# than assembled hopefully:
#   diffusers 0.42.1    -> huggingface-hub>=1.32,<3 ; safetensors>=0.8.0 ; torch>=2.6
#   transformers 5.22.2 -> huggingface-hub>=1.31,<3 ; safetensors>=0.8.0 ; tokenizers>=0.23.1,<0.24
# huggingface-hub 2.4.0 and safetensors 0.8.0 satisfy both, so there is nothing left to search for.
#
# WHY diffusers 0.42.1 AND NOT THE ORIGINAL 0.33.1: the model's own model_index.json at the pinned
# revision declares `_class_name: QwenImagePipeline` and `_diffusers_version: 0.36.0.dev0`. 0.33.1 contains
# no QwenImagePipeline, no QwenImageTransformer2DModel and no AutoencoderKLQwenImage.
